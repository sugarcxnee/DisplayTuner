# DisplayTuner

macOS 纯菜单栏副屏分辨率调整工具。核心用途是列出 Mac 当前所有显示器(内置屏 / iPad Sidecar 随航 / 外接显示器),为**副屏**单独选择分辨率、刷新率和 HiDPI 模式,改善 iPad 随航作为扩展屏时"很糊"的问题。

系统给随航屏的模式上限卡在原生分辨率(如 1180×820)时,可用**虚拟显示器增强**:创建高分辨率虚拟屏并镜像到 iPad,把随航工作区扩大 ×1.5 / ×2 / ×2.5 倍——[使用指引见下文](#-使用虚拟显示器扩大-ipad-随航工作区)。

```
菜单栏图标 ▾
├── 当前显示器:内置屏 / Sidecar / 外接屏
├── 刷新显示器
├── ─────────────────────
├── iPad Sidecar(主屏/Sidecar 徽标)— 当前模式摘要
│   ├── 当前模式:1920×1080 HiDPI @ 60Hz
│   ├── 推荐模式 / 其他模式(当前模式带 ✓)
│   ├── 当前随航连接未提供更高分辨率模式(仅当系统确实没给)
│   ├── 增强模式(实验)(开启实验增强且系统揭示了隐藏模式时)
│   ├── 过滤:仅 HiDPI / ≥ 当前分辨率 / 16:10(可叠加)
│   ├── 恢复默认模式
│   └── 高级 ▸ 实验性 Sidecar 增强
│            ▸ 虚拟屏(实验):×1.5 / ×2(推荐) / ×2.5 三档更大工作区,
│               创建时全部档位注册进模式表;运行中可原地切档(不重建),
│               随时可停止;新建会话有 10 秒倒计时自动还原
├── ─────────────────────
├── ✓ 自动恢复上次配置
├── 实验性 Sidecar 增强(附私有符号探测状态)
├── 开机启动
├── 日志级别:错误 / 信息 / 调试
├── 打开日志文件
├── 关于 DisplayTuner
└── 退出
```

## 系统要求

- macOS 13 Ventura 或更高
- Apple Silicon / Intel 均可
- 无第三方运行时依赖

## 构建与运行

```bash
# 一次性环境准备(需要 Xcode + XcodeGen)
bash scripts/bootstrap.sh

# 生成工程并构建 Release App(ad-hoc 签名,可直接运行)
make build

# 启动(菜单栏应用:无 Dock 图标、无主窗口)
make run
```

构建产物在 `build/Build/Products/Release/DisplayTuner.app`,可拖入 `/Applications` 使用。

### 运行测试

```bash
# 推荐:Xcode 工程测试(与 CI 完全一致)
make test

# 或直接用 Swift Package Manager(快速内环)
make test-spm
```

### 命令行导入导出配置

```bash
DisplayTuner.app/Contents/MacOS/DisplayTuner --export-config ~/backup.json
DisplayTuner.app/Contents/MacOS/DisplayTuner --import-config ~/backup.json
```

## 🖥 使用虚拟显示器扩大 iPad 随航工作区

### 这适合你吗?

如果你的 iPad 随航屏分辨率上限"卡"在类似 1180×820 的数值——这通常**就是 iPad 的原生逻辑分辨率**(如 10.9 英寸款物理屏 2360×1640 的 2 倍点对点映射),系统没有提供更高的缩放档——那么常规的分辨率切换帮不了你,Display Maestro 也一样,因为系统层面就没有更多模式可选。

唯一的出路是 BetterDisplay 式的**虚拟显示器方案**:在 Mac 上创建一块高分辨率的虚拟屏作为真实工作区,再把 iPad 镜像到它上面。iPad 显示的是虚拟屏的镜像,你的桌面空间因此扩大——DisplayTuner 把这套方案做成了菜单里的三个档位。

### 操作步骤

1. 连接 iPad 随航(扩展屏模式),等待几秒让系统稳定;
2. 点击菜单栏图标 → 找到 iPad 那一栏(带 Sidecar 徽标)→ **高级 ▸ 虚拟屏(实验)**;
3. 选择一档:

| 档位 | 以 1180×820 为例 | 说明 |
|---|---|---|
| ×1.5 | 1770×1230 | 舒适,界面元素略小 |
| **×2(推荐)** | **2360×1640** | **等于 iPad 物理像素,整数倍缩放最干净** |
| ×2.5 | 2950×2050 | 超大工作区,界面元素明显变小 |

4. 弹出系统确认框后点**"保留"**(或等 10 秒自动还原,新建会话有安全倒计时);
5. 在控制栏的屏幕镜像或者设置中的显示设置里把iPad设置为虚拟屏的镜像，完成。iPad 现在显示虚拟屏的镜像,工作区按所选倍数扩大。

### 运行中的操作

- **换档**:回到同一个菜单,直接点另一档——原地切换,**不重建虚拟屏、不打断镜像、无需确认框**,即点即生效(失败会自动切回旧档);
- **停止**:菜单最后一项"停止虚拟屏",或直接拔掉/断开 iPad(自动停止并清理);
- 镜像期间 iPad 那一栏的常规分辨率项会被禁用并提示"分辨率由虚拟屏决定"——这是有意设计:镜像中 Sidecar 的模式由虚拟屏决定,手动改会被镜像约束拉回,想改分辨率请切换虚拟屏档位。

### 效果与取舍

- ✅ 工作区(可摆放窗口的逻辑空间)按所选倍数扩大;
- ⚠️ 界面元素、文字随之变小——这与系统"更多空间"缩放档是同一种取舍;
- ⚠️ iPad 端画面经过缩放,文字渲染密度低于原生(×2 档因为整数倍缩放,观感最接近原生);
- ⚠️ 无线连接带宽紧张时系统可能压缩画质,有线 USB-C 连接体验更好。

### 疑难解答

| 现象 | 说明 |
|---|---|
| 菜单显示"虚拟屏不可用(缺少私有类)" | 当前系统缺少 `CGVirtualDisplay` 私有类(极少数系统版本会移除),该功能如实禁用,其余功能不受影响 |
| 新建虚拟屏后 10 秒没点"保留" | 安全倒计时自动还原——重新选档并点"保留"即可 |
| 切档/停止后菜单还显示"运行中" | 菜单每次打开都重新枚举,关掉菜单重新点开即刷新 |
| iPad 断开后重连 | 虚拟屏会话已自动清理,重新选档即可;确认过的档位偏好已记住 |
| 不开虚拟屏也能给 iPad 切高分辨率,但过一会儿被弹窗切回、循环往复 | 历史镜像会话会把系统生成的高分辨率档**留在 iPad 的模式表里**——这些档能设置但系统不持续认可,会自动拉回默认档。DisplayTuner 的自动恢复与系统"对抗"时会反复弹窗;现在已在弹窗上点**"还原/不保留**即清除该偏好并进入长冷却,连续确认多次仍被拉回则本次运行内放弃,循环会自行停止。想彻底回到干净状态:菜单里对该显示器执行**"恢复默认模式** |
| 镜像期间系统设置里改 iPad 分辨率无效 | 正常现象:镜像成员的显示内容跟随虚拟屏,系统设置里的切换会被镜像约束覆盖;请改虚拟屏档位 |

## ⚠️ 安全设计:倒计时回滚

**修改显示模式可能造成黑屏、花屏或布局错乱。** DisplayTuner 的每次切换都走同一条安全路径:

1. 应用前保存当前模式;
2. 应用后立即验证实际生效模式与期望一致,不一致自动恢复;
3. 弹出系统确认框,**10 秒内不点"保留更改"就自动还原**;
4. 应用失败立即回滚并记录日志;
5. 显示器拔出 / Sidecar 断开导致回滚失败时,如实记录,不会悬挂状态。

对主显示器的修改会在确认框中给出额外警告。

## 限制说明(请务必阅读)

- **Sidecar 更高分辨率不是无中生有**:可用模式由 iPad 型号、macOS 版本、连接方式(有线/无线)共同决定。系统不暴露更高模式时,菜单会如实显示"当前随航连接未提供更高分辨率模式",DisplayTuner 不会伪造不存在的模式。
- **实验性 Sidecar 增强**默认关闭。其公开部分用 `kCGDisplayShowDuplicateLowResolutionModes` 揭示系统隐藏模式;私有部分仅以 dlopen/dlsym 探测 DisplayServices 框架符号,**探测不到就如实报告并降级到公共 API**。
- **虚拟屏(实验)**:实现原理是用 CoreDisplay 私有框架的 `CGVirtualDisplay` 类(纯运行时调用,不链接私有框架)创建虚拟屏、公共 CG API 激活模式与镜像。效果与取舍见上文[使用指引](#-使用虚拟显示器扩大-ipad-随航工作区);同样有 10 秒倒计时自动还原,Sidecar 断开自动停止并清理。
- **App Store**:应用包含私有框架的运行时探测(不直接链接),App Store 审核可能不接受;本工具按自用/开源分发设计。
- **开机启动**使用 `SMAppService`,要求 App 位于稳定位置且签名有效;开发期 ad-hoc 签名注册可能失败,菜单会如实反映状态。
- 回退 ID(无序列号的显示器)在重新插拔后可能变化,自动恢复按"稳定 ID + 模式仍可用"双条件匹配,不会盲切。

## 日志与隐私

- 日志输出到控制台和 `~/Library/Application Support/DisplayTuner/logs/DisplayTuner.log`(自动轮转);
- 菜单"打开日志文件"可直接定位;
- 日志不记录序列号、设备名等隐私信息,显示器仅以"类别 + 短哈希"标识。
